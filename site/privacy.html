What the widget reads, and what it never does.

AI Limits is a desktop widget that shows how much of your AI subscription windows you have used. It runs entirely on your computer. There is no account to create, no server of ours in the middle, and nothing it learns about you ever leaves your machine except the requests described below, which go to the providers themselves. This page describes version 0.7.1.

It asks before it reads

Nothing that belongs to another program is read until you allow it. Each question names the file it would read and the only server its token would be sent to. On a first start the widget shows a welcome with the tools found on this PC, each with a tick; it finds them only by whether their folder exists, without opening anything inside. Cancel reads nothing. If you update from 0.7.0, the providers you already had keep working, and one window lists every file read and every server contacted. To stop reading a tool, untick its rows in Rows and models; unticking Model, Version and Effort takes back the reads for model labels.

What it reads, once allowed

To show a limit, the widget asks the provider the same way its own command-line tool does. So it reads the sign-in those tools already keep on your machine, read-only, unless you choose another source under the provider's Sign-in in Rows and models: a usage token, or a key or token you paste. Only the source chosen is used.

  • Claude — the Claude Code sign-in in %USERPROFILE%\.claude\.credentials.json.
  • OpenAI Codex — the Codex CLI sign-in in %USERPROFILE%\.codex\auth.json (in CODEX_HOME when that is set).
  • GitHub Copilot — a token you paste, or the token the GitHub CLI keeps for github.com (gh auth token --hostname github.com, asked at most every 15 minutes, and once more at once when GitHub refuses a token gh gave earlier).
  • Google Antigravity — the Antigravity CLI's sign-in in Windows Credential Manager (gemini:antigravity). It is renewed only when you run the CLI, agy; opening the Antigravity editor does not renew it, and the editor's own sign-in is never read. Until you run agy again, the row reads "token expired". Google has suspended some accounts for using Antigravity's sign-in outside Antigravity; AI Limits only reads the quota, once per update, but the risk is yours, and its question says so before anything is read. The older Gemini CLI sign-in, %USERPROFILE%\.gemini\oauth_creds.json, is no longer read.
  • xAI Grok — the Grok CLI sign-in in %USERPROFILE%\.grok\auth.json (in GROK_HOME when that is set).
  • Cursor — no file of Cursor's. You sign in once from Rows and models, Cursor's Sign-in, Sign in to Cursor..., on Cursor's own sign-in page at cursor.com, in your browser. Cursor has no sign-in for other apps, so the widget signs in as the Cursor editor's client, and keeps that session (about 60 days) in Windows Credential Manager. It tries to renew that session in its last week, at most once a day; when the session ends, you sign in again. The editor's own sign-in is never read or touched.

Model labels are optional and allowed separately. With them, the widget reads each running tool's own settings file (for example %USERPROFILE%\.claude\settings.json, config.toml of Codex or Grok, settings.json of the Copilot or Antigravity CLI, and from Cursor's state.vscdb only the model chosen for its Agent), and, if you choose "Last used", the end of the newest Claude Code or Codex CLI session file (at most its last 1 MB). Only the model's name and its effort are kept, in memory, and nothing from these files is sent anywhere. Nothing is ever written to or created in another program's folder, Cursor's included.

The widget never writes to those files, never refreshes or rotates a tool's token, and never signs you out of anything. The one session it renews is its own Cursor session. If a sign-in is missing or expired, that provider's row goes grey or hides; nothing else happens.

Where it sends

Each token is sent only to the provider that issued it, over HTTPS, to fetch your usage: api.anthropic.com (Claude), chatgpt.com (Codex), api.github.com (Copilot), cloudcode-pa.googleapis.com and daily-cloudcode-pa.googleapis.com (Antigravity), cli-chat-proxy.grok.com (Grok) and api2.cursor.sh (Cursor). The Cursor sign-in page, cursor.com, opens in your browser; the widget sends nothing there itself. A request that carries a token never follows a redirect, so the token cannot be passed on to another server.

One usage request per running provider per update cycle, no more often than once a minute, and none at all while the computer is idle or locked. The few extra requests, exactly: Cursor's plan at most once an hour, its Grok Bot share only while you show that row, and its session renewal only in the session's last week, at most once a day; Antigravity's project once a session, and its second quota endpoint only when the first gave nothing usable. A token a server refused is not sent again for a while. A provider you switched off, or did not allow, is never contacted. A usage token you paste is checked with one request to the same server it is meant for.

Requests use the proxy set in Windows, or the one an HTTPS_PROXY or HTTP_PROXY variable names; the ailimits-auth command-line tool follows only the variables.

A copy installed with the AI Limits installer also asks api.github.com once a day whether a newer release exists, and downloads it from the release on GitHub only to install it while you are away. It checks the digest GitHub publishes for the installer and the release's own signature first, and installs nothing that fails either check. That request carries the standard user agent ailimits/<version> and nothing about you. The Microsoft Store, Scoop and portable copies never do this: their own channel updates them, and they do not contact GitHub at all.

There is no telemetry, no analytics, no crash reporting and no advertising. Nothing is sent to us, because there is no us to send it to: the project has no server.

What it stores

Everything below stays on your computer.

  • Settings — in %APPDATA%\AiLimits\config.toml: layout, palette, the rows shown, which providers are on and what you allowed it to read. It holds labels, never secrets.
  • Keys, tokens and the Cursor session — a key or usage token you add, and the widget's own Cursor session, go into Windows Credential Manager under the service ailimits, never into a file.
  • The last readings — in provider-cache.json beside the settings, so the widget can show them, marked with their age, while a provider is unreachable.
  • The notification icon — icon.png, so Windows can show the app's icon on its notifications (installer and portable copies).
  • Alerts given — in alerts.json, so a restart does not repeat a usage alert.
  • The last update attempt — in update-attempt.json, installer copies only, so an update that failed is not retried by itself.
  • A crash note — if the widget ever crashes, one line in crash.log: the time, the version and the place in the code, never the message's text. A start that failed may name a local file path there. It is not sent anywhere.
  • A log — only if you set AILIMITS_LOG yourself. Tokens and clipboard contents are never written to it.

Removing it

The installer's uninstaller removes the app, the folder %APPDATA%\AiLimits with everything listed above, every Credential Manager entry the widget created (keys, usage tokens and its Cursor session), its autostart entry and its notification registration. It works offline.

The Microsoft Store cannot run a step of ours at uninstall. Before removing the Store version, use each provider's Sign-in in Rows and models to sign out of Cursor and remove a key or token you pasted, or delete the ailimits entries under Windows Credentials in Credential Manager afterwards. The CLI sign-ins the widget only read are not ours and are never touched either way.

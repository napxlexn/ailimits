# CONFIG.md — конфігураційний файл

Розташування: `%APPDATA%\AiLimits\config.toml`. Створюється автоматично
при першому запуску; кожна зміна з контекстного меню зберігається сюди.
Невідомі поля і провайдери ігноруються (старі конфіги ніколи не ламають
парсинг). Читаються UTF-8 з BOM чи без нього і UTF-16 з BOM (кодування
Блокнота).

Коли файлом не вдається скористатися, його ніколи не перезаписують
дефолтами:

- **Його не вдається прочитати** (його тримає інша програма, права на
  теку): читання повторюється близько 2 секунд. Далі програма працює з
  нічим не увімкненим і без вітання, лишає файл точно таким, яким він є, і
  нічого поверх нього не зберігає до перезапуску. Про це каже одне
  повідомлення.
- **Його не вдається зрозуміти** (зламаний TOML, текст не в UTF-8 чи
  UTF-16): його відкладають як `config.toml.<UTC yyyymmdd-hhmmss>.corrupt`
  (з `-2`, `-3`... коли ця назва зайнята; попередній ніколи не
  замінюється). Програма стартує як після нового встановлення, а старі
  налаштування лишаються в тому файлі. Одне повідомлення його називає.
- **Його не вдається ні зрозуміти, ні відкласти**: він лишається, і нічого
  не зберігається, як і для файлу, який не вдається прочитати.

Поруч програма тримає власні файли (деінсталятор інсталятора прибирає їх
усі разом із текою):

| Файл | Що в ньому |
|---|---|
| `provider-cache.json` | останні відомі метрики з майбутнім скиданням, щоб вони пережили перезапуск. Пишеться, коли змінюються значення, ліміти чи час скидання (з точністю до хвилини), інакше не частіше ніж раз на 10 хвилин, щоб оновити час запиту, і при виході. Після аварії кешований рядок може показати вік щонайбільше на 10 хвилин більший за справжній, але ніколи не менший. |
| `alerts.json` | які сповіщення про поріг уже були, для кожного провайдера (вікна, про які сповіщено, і останнє сповіщення), щоб перезапуск їх не повторював. Записи, старші за добу, зникають. |
| `update-attempt.json` | остання спроба самооновлення: версія, шлях до завантаженого інсталятора і чи вже сказано про незавершену спробу. Лише копії з інсталятора. |
| `crash.log` | один рядок на аварію: UTC-час, версія, потік, файл:рядок:стовпець джерела. Текст паніки не пишеться ніколи. Ротується на 64 КБ у `crash.log.1`. Невдалий старт пише `could not start: <помилка>` (може назвати локальний шлях, наприклад до config.toml). |
| `ailimits.log` | лише поки задано `AILIMITS_LOG` чи `RUST_LOG`; ротується на 5 МБ у `ailimits.log.1`. Токени не пишуться ніколи. |
| `config.toml.<штамп>.corrupt` | конфіг, який не вдалося зрозуміти, відкладений, як описано вище. |

## Повний приклад

```toml
[general]
# Інтервал оновлення в секундах (меню: 60 / 300 / 900 / 1800; мінімум 60).
# Опитування стає на паузу при бездіяльності/заблокованому екрані та
# відступає, коли провалився весь цикл (120, 240, далі 300 с при інтервалі
# 60 с); після сну чи паузи простою, перший цикл якої не отримав жодної
# відповіді, одна повторна спроба йде через 20 с. Endpoint Claude ще й
# обмежений на боці сервера, тож його оновлення інколи займає 2–3 хвилини
# незалежно від цього налаштування.
update_interval_secs = 60
# Індикатор на панелі завдань (меню: Indicator): "tray" — трей-іконка
# 16px із двох концентричних кілець, що несуть два найнавантаженіші
# провайдери; монохромна, у темі системної панелі завдань; "panel_rows" / "panel_grid" (застарілий
# псевдонім) — прозорий overlay зліва від трею: layered-вікно з per-pixel
# alpha, малюються лише цифри й бари. Показує перші два провайдери в
# порядку віджета (відсоток + бар, розмір годинника), монохром, слідує
# СИСТЕМНІЙ світлій/темній темі; решта — у tooltip. Стежить за
# авто-приховуванням і шириною трея подієво, без полінгу. "bars" —
# застаріла трей-іконка; "off" — нічого. Замінює застарілий прапорець
# show_tray_icon (ігнорується). Яких провайдерів показують панель і
# трей-іконка, можна вибрати: [ui.rows] taskbar нижче.
indicator = "tray"
# Автооновлення (меню: Automatic updates). Сама оновлюється лише копія, яку
# поставив наш інсталятор; копія зі Store, Scoop, портативна чи власна
# збірка нічого не питає в GitHub, і в її меню такого пункту немає. Коли
# true, програма перевіряє GitHub на новіший реліз (~через 30 с після
# старту, далі щодоби), завантажує інсталятор і звіряє і SHA-256, який
# GitHub публікує для нього, і Ed25519-підпис релізу, чекає, поки вас не
# буде 5 хвилин (без вводу або із заблокованим сеансом), тихо встановлює
# його й запускається знову. Версію, оновлення до якої не завершилось,
# сама вона більше не пробує; наступний старт один раз про це каже.
# Відсутнє в старих конфігах → true.
auto_update = true
# Ручне зміщення позиції панелі, у пікселях, застосовується після
# обчисленого розташування. Обидва за замовчуванням 0 — без коригування.
# Обмежується діапазоном -200..200 — одруківка не може виштовхнути панель
# за межі робочого столу. Інструмент для відновлення на машинах, де
# автоматичне розташування не спрацьовує: заміна shell (StartAllBack,
# ExplorerPatcher), нетипові лейаути панелі завдань, лейаути на сенсорних
# пристроях. Навмисно лише в конфізі, без пункту меню.
panel_offset_x = 0
panel_offset_y = 0
# На яку панель завдань кріпиться міні-панель (меню: Indicator -> Display;
# це підменю з'являється лише коли існує вторинна панель завдань, і
# будується при старті, тож підключення монітора пізніше вимагає рестарту,
# щоб пункт з'явився). "primary" (дефолт), або { secondary = N }, де N
# рахує вторинні панелі завдань з 0, зліва направо за позицією монітора —
# напр. { secondary = 0 } для першої (найлівішої) вторинної панелі.
# Вторинні панелі завдань існують лише коли Windows налаштована показувати
# панель завдань на всіх дисплеях. Якщо обраний дисплей зник (монітор
# від'єднано, або цю опцію Windows вимкнено), або значення нерозпізнане,
# панель повертається на primary, а не ламає весь конфіг-файл.
panel_display = "primary"

[window]
pos_x = 50
pos_y = 50
# Прозорість фону 0.10–0.85.
opacity = 0.45
# Поверх всіх вікон.
pinned = false
# Заблокована позиція — drag вимкнено (незалежно від `pinned`).
locked = false

[ui]
# Палітра: default / ocean / sunset / forest / neon / ice / rose / slate.
palette = "default"
# Насиченість палітри 0–100 (0 = грейскейл, 100 = повний колір).
saturation = 55
# Яскравість тексту і барів 20–100.
brightness = 100
# Монохромний режим (перекриває палітру).
monochrome = false
# Лейаут: "vertical" або "horizontal".
layout = "vertical"
# Рівень деталізації: "compact" / "medium" / "expanded".
detail = "compact"
# Крок ширини для розкладки з горизонтальними смужками (rows); вертикальна
# розкладка його ігнорує. "full" / "three_quarters" / "half" (меню: Width).
width_scale = "full"
# Розташування колонок для вертикальних смужок; розкладка rows його ігнорує.
# "row" (поруч, широкий і низький) або "column" (стовпчиком, вузький і високий)
# (меню: Arrangement).
column_flow = "row"
# Прогноз burn-rate ("~Xh to limit", коли використання росте; меню: Forecast).
# Ніколи не замінює зворотний відлік до скидання — показується лише коли
# майбутній reset невідомий.
show_forecast = false

# Рядки (меню: Rows and models...). Записується лише після вибору; без
# нього в кожного провайдера один рядок, як і раніше. Власний рядок
# провайдера — його id, додатковий рядок — provider.part, і є лише такі,
# кожен там, де провайдер рахує його окремо: claude.opus, claude.sonnet,
# claude.fable (тижневі, якщо план їх має), antigravity.cg (пул Claude і GPT),
# grok.build, cursor.bot (Grok Bot; Cursor питає про нього лише поки цей
# рядок вибрано). Віджет і підказка вибираються окремо; панель на панелі
# задач і іконка трею лишаються по одному на провайдера. Невідомі id
# ігноруються і зберігаються. Якщо вибрані рядки ще не мають даних, віджет
# пише "Nothing to show yet"; клік відкриває вікно вибору.
# taskbar: провайдери, яких показують панель на панелі задач і трей-іконка
# (колонка Taskbar у вікні), щонайбільше два, у порядку віджета.
# Записується лише після вибору; без нього вони показують те, що й завжди
# (панель — перших двох провайдерів, що працюють, кільця трею — двох
# найнавантаженіших), а вікно відмічає перших двох. Коли жоден зі списку
# не працює, показуються перші два, що працюють. Провайдер зі списку
# працює й далі, навіть якщо жоден його рядок у віджеті чи підказці не
# відмічено.
[ui.rows]
widget  = ["claude", "claude.opus", "codex"]
tooltip = ["claude", "claude.opus", "claude.sonnet", "codex", "grok"]
taskbar = ["claude", "grok"]

# Підписи моделі (меню: Rows and models...). Частини для кожної поверхні:
# "model", "version" (лише разом із "model"), "effort" (можна окремо).
# Порожньо — без підпису. Для них читається файл налаштувань кожного
# інструмента, що працює, тож перша галочка спершу питає ([reads]
# tool_settings). Віджет малює підпис окремим рядком в Expanded і в
# розкладці стовпцями, а в Medium — на тому місці рядка метаданих, що лишає
# скидання (або теж окремим рядком, коли це місце вужче за назву); Compact
# лишає його підказці. У вузьких місцях спершу відпадає effort, потім
# версія, потім модель; слово ніколи не ріжеться.
# source: "configured" (модель, вибрана в інструменті) або "last_used"
# (найновіша сесія Claude Code чи Codex CLI; спершу питає, [reads]
# last_session; інші інструменти й далі показують вибрану модель).
[ui.model]
widget  = ["model"]
tooltip = ["model", "version", "effort"]

# Ваші назви моделей, за id, який зберігає інструмент. Автоматична назва
# складається за одним правилом без таблиці (claude-opus-5-5 -> "Opus 5.5"),
# тож нова модель не потребує оновлення. Модель, спільна для кількох
# інструментів, має одну назву. Власний роутер інструмента має назву для
# кожного інструмента окремо, під ключем "provider:id" ("copilot:auto",
# "cursor:auto"); назва, яку старіша збірка зберегла під голим "auto", діє
# для обох, доки один із них не перейменують. Назва мусить вміщатися в
# найвужче місце, де віджет малює назву моделі, — приблизно десять
# звичайних символів; вікно вибору там зупиняє введення. Порожня назва
# повертає автоматичну.
[ui.model.names]
"claude-opus-5-5" = "Opus 5.5"
"copilot:auto" = "Auto"

# Провайдер за замовчуванням, якого бракує у старому конфігу, додається

app_sign_in   = ["cursor"]

# ([ui.model]), хай як інструмент входить; база стану Cursor — один із них.
# Якщо зняти останню з Model, Version і Effort на обох поверхнях, це поле і
# last_session знову стають false.
tool_settings = false
# Кінець найновішого файлу сесії Claude Code / Codex CLI — для останньої
# використаної моделі ([ui.model] source = "last_used"). Повернення до
# "As set in the tool" знову ставить false.
last_session  = false
# Одноразове вікно, яке ще треба показати: "welcome" (свіже встановлення),
# "update_notice" (перший запуск після оновлення з 0.7.0 чи старішої) або
# "none".
pending       = "none"
```

## Секрети

Конфіг ніколи не містить ключів чи токенів — лише мітки. Значення живуть
у Windows Credential Manager під service `ailimits`:

| Мітка | Призначення |
|---|---|
| `claude_api_key` | API ключ Claude (метод api_key) |
| `claude_usage_token` | ручний usage-токен підписки Claude |
| `codex_usage_token` | ручний usage-токен ChatGPT/Codex |
| `copilot_pat` | GitHub PAT (замість gh CLI) |
| `cursor_session` | власний сеанс Cursor віджета, як UTF-8 JSON: токен, його строк дії, остання спроба оновлення, чи завершив його Cursor (меню: *Sign in to Cursor...* / *Sign out of Cursor*; CLI: `ailimits-auth login cursor` / `logout cursor`) |

Деінсталятор інсталятора прибирає всі п'ять (через `ailimits-auth`,
локально, без мережі). Копія з Microsoft Store не має нашого кроку
деінсталяції: перед її видаленням скористайтеся пунктами меню *Sign out of
Cursor*, *Remove key* і *Remove usage token* або видаліть записи `ailimits`
у *Windows Credentials* у Credential Manager.

Ключ чи usage-токен, вставлений із меню, приймається лише у формі того, що
просили: API-ключ і usage-токен Claude починаються з `sk-ant-`; токен
Copilot — `ghp_...`, `github_pat_...`, `gho_...`, `ghu_...` або класичний
40-символьний hex; usage-токен Codex — JWT (`eyJ...`, три частини). Від
10 байт до 8 КБ, без пробілів. Повідомлення каже, що очікувалося, і ніколи
не цитує буфер обміну, який ніколи не логується. Далі usage-токен
перевіряється одним запитом до того самого хоста, куди його надсилає
провайдер: відхилений (401/403) не зберігається; без відповіді, яка б
сказала так чи ні, зберігається з тостом "stored, but not checked: ...".
Друге вставлення чи видалення під час перевірки її замінює.

## Що читається і коли

Кожне читання файлу іншого інструмента необов'язкове, і програма спершу
питає:

- **Свіже встановлення нічого не читає.** Віджет і трей пишуть «Choose what
  to show», а вікно вибору відкривається саме як вітання. Його запитання
  «Show the tools found on this PC?» має галочку для кожного знайденого
  інструмента, знайденого лише за тим, чи існує тека (всередину програма не
  заглядає), і називає кожен файл, що буде прочитано, і кожен сервер. Від
  початку відмічені інструменти, знайдені за власною текою:
  `%USERPROFILE%\.claude`; `CODEX_HOME` або `%USERPROFILE%\.codex`;
  `COPILOT_HOME` або `%USERPROFILE%\.copilot`; `%APPDATA%\Antigravity` або
  `%USERPROFILE%\.gemini\antigravity-cli`; `GROK_HOME` або
  `%USERPROFILE%\.grok`; `%APPDATA%\Cursor`. Інструмент, знайдений лише за
  суміжною текою (`%APPDATA%\GitHub CLI` для Copilot, `.gemini` для
  Antigravity), показано без галочки з поясненням; коли знайдено лише такі,
  запитання не відкривається, а їхні рядки тільки позначено «found on this
  PC». Allow запускає лише відмічені інструменти і неактивна без жодної
  галочки; Cancel нічого не читає і лишає вибір вам.
- **Перша галочка будь-якого іншого інструмента один раз питає**, називаючи
  файл і сервер. Поки інші інструменти, знайдені на цьому ПК за власною
  текою, ще не дозволені, це запитання пропонує *Allow all*: воно запускає
  і їх, вмикаючи, бо нова інсталяція й оновлення лишають кожного
  невикористаного провайдера вимкненим. Інструмент, який ви дозволили, а
  потім вимкнули в меню Providers, зберігає дозвіл, і його не чіпають. У
  вікні, де вже відповіли на запитання вітання, його не пропонують.
- **Вітання й повідомлення після оновлення відкриваються тихо.** Вони не
  забирають фокус клавіатури, тож Enter чи Space нічого не дозволяють, поки
  Tab чи стрілка не переведе фокус на кнопку. Вони чекають, поки вікно на
  весь монітор (гра, відео, браузер на F11, слайд-шоу) на передньому плані,
  і відкриваються при наступній зміні вікна на передньому плані, наступному
  оновленні чи наступному запуску програми. Відповіддю вважаються відповідь
  на запитання, хрестик, Esc, Alt+F4, OK чи Review. Клік поруч із коробкою
  або перехід в інше вікно, коли фокус уже був у ньому, закриває його без
  відповіді, тож воно відкриється знову при наступному старті.
- **Після оновлення з 0.7.0 чи старішої** нічого не зупиняється: увімкнені
  провайдери читають далі, як раніше (`sign_in` заповнюється ними), а одне
  вікно один раз перелічує всі файли, які читаються, і всі сервери, до яких
  програма звертається. Провайдер, якого стара версія не мала (для 0.7.0 це
  Grok і Cursor), додається вимкненим і питає, коли його позначити.
- **Конфіг, який не вдається зрозуміти**, відкладається (див. угорі), і
  програма стартує як після свіжого встановлення: що дозволяв утрачений
  файл, невідомо, тож нічого не читається, поки користувач не вибере знову.
  Порожній конфіг або конфіг без `[[providers]]` теж вважається свіжим
  встановленням. Конфіг, який не вдається прочитати, лишається, і програма
  працює з нічим не увімкненим до перезапуску.
- **Свіже встановлення ще й вимикає всіх провайдерів**, а не лише нічого не
  дозволяє: навіть старіша версія, запущена потім на тому самому конфігу,
  читає тільки дозволене.
- **Щоб припинити читання інструмента**, зніміть усі його рядки в Rows and
  models (або галочку Enabled у меню Providers). Його кешовані числа,
  остання помилка, тренд і позначки сповіщень очищаються. Якщо зняти
  останню з Model, Version і Effort на обох поверхнях, читання налаштувань і
  сесій відкликаються (`tool_settings` і `last_session` стають false);
  повернення до «As set in the tool» відкликає читання сесій. Наступна
  галочка знову питає.
- **Провайдер, налаштований власним входом програми** (вставлений ключ чи
  usage-токен, вхід у Cursor з меню), ніколи не має прочитаного входу
  інструмента. Його файл налаштувань читається для підпису моделі, коли це
  дозволяє `tool_settings`, як і для кожного провайдера, що працює.
- **Де інструменти тримають свої файли**, можна змінити через `CODEX_HOME`,
  `GROK_HOME` і `COPILOT_HOME`. Кожна змінна переносить усі файли свого
  інструмента, які читає програма: `auth.json`, `config.toml` і сесії
  Codex; `auth.json` і `config.toml` Grok; `settings.json` Copilot CLI.
  Шлях має бути абсолютним: відносний означає, що файли цього інструмента
  не читаються взагалі (ніколи не тека відносно програми й ніколи не тека
  за замовчуванням), і на цьому ПК цей інструмент теж не шукається.
  `CLAUDE_CONFIG_DIR` Claude Code і `GH_CONFIG_DIR` gh не враховуються.
- **`ailimits-auth status`** — діагностика, яку ви запускаєте самі. Вона
  нічого не змінює: ніколи не створює, не перейменовує й не пише
  `config.toml`. Вхід іншого інструмента вона читає лише там, де може віджет
  (`[reads] sign_in`), а інакше друкує «found (not read: ...)». `auth.json`
  Codex і застарілий `oauth_creds.json` Gemini лише перевіряються на
  наявність; gh питають лише про github.com
  (`gh auth token --hostname github.com`, тайм-аут 10 с, вивід
  відкидається); з Cursor показується лише власний сеанс віджета. Вона
  друкує режим читання кожного провайдера і стан `[reads]`, а токен —
  ніколи.
- **Інші команди `ailimits-auth`** (`set`, `remove`, `set-usage-token`,
  `login`) відмовляються працювати з `config.toml`, який не вдається
  прочитати чи зрозуміти («nothing was changed»). Віджет записує свої
  налаштування при виході, тож перед такою командою закрийте його, а потім
  запустіть.

Файли й сервери кожного провайдера — у [PROVIDERS.md](PROVIDERS.md) і в
`src/consent.rs`, звідки беруть текст запитання; шляхи визначає
`src/config/paths.rs`.

Rust-структури — у `src/config/schema.rs`; цей файл є єдиним джерелом
правди для схеми.

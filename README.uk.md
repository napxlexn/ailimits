## Що він робить

- **Тільки читає.** Він читає токени, які офіційні CLI-інструменти вже
  зберігають на твоїй машині. Ніколи не оновлює і не ротує їх, тож не може
  розлогінити тебе з цих інструментів. Єдиний виняток — Cursor: застосунок
  входить у нього з власним сеансом і ніколи не читає й не чіпає вхід
  редактора. Ключі, які ти додаси сам, і цей сеанс зберігаються у Windows
  Credential Manager. Застосунок звертається лише до endpoint'ів самих
  провайдерів (а копія з інсталятора — ще й до GitHub по оновлення), робить
  один запит використання на провайдера за цикл (плюс кілька допоміжних
  запитів, перелічених у
  [docs/uk/PROVIDERS.md](docs/uk/PROVIDERS.md#запити-за-цикл)), іде через
  проксі, заданий у Windows, і не надсилає телеметрії.
- **Питає, перш ніж читати.** Нічого, що належить іншому інструментові, не
  читається, поки ти не дозволиш, і кожне запитання називає файл і куди
  надсилається його токен. Про кожне питає один раз, а *Forget permission*
  відкликає дозвіл одним кліком. Див. [Що читається і коли](docs/uk/CONFIG.md#що-читається-і-коли).
- **Мінімум налаштувань.** При першому запуску знайдені інструменти вже
  відмічені, і одне запитання називає кожен файл входу, який буде прочитано:
  досить натиснути «Allow». Далі твоя звичайна робота з CLI тримає їхні токени дійсними,
  тож більше нема чого конфігурувати. Лише Cursor просить один раз увійти в
  *Settings*.
- **Низьке навантаження, виміряне на запущеному застосунку.** 0.014% одного
  ядра CPU, нуль використання GPU (рендеринг на CPU), робочий набір 53 МБ (25 МБ
  приватної пам'яті), виміряно для 0.7.1 23.11.2026; без підняття роздільності
  таймера (21.11.2026); exe на 4 МБ. Відтворити:
  `bench/perf_audit.ps1`; повні цифри в
  [docs/uk/ARCHITECTURE.md](docs/uk/ARCHITECTURE.md#споживання-ресурсів-виміряно-не-оцінено).
- **Застарілі дані позначені як застарілі.** Значення, яке перестало
  оновлюватись, сіріє і показує свою давність. Вікно ліміту, яке гарантовано
  скинулось, показує `≈0%`. Застосунок не заповнює прогалини здогадками.
  Поки тебе немає, опитування стоїть на паузі, і цей час не рахується: нічого
  не сіріє лише через те, що ти відійшов.
- **Самодостатній.** Статично злінкований, тож не потребує Visual C++
  Redistributable і не тягне DLL. Інсталятору не потрібні права
  адміністратора.

## Встановлення

> **Оновлюєшся з 0.7.0 (чи 0.6.x), а шлях твого профілю чи теки TEMP
> містить не англійські літери (наприклад, кирилицю), `&` чи `%`?**
> Оновлювач старої версії на такому шляху ламається: щойно вийде 0.7.1, він
> може закривати AI Limits приблизно за пів хвилини після кожного старту.
> Встанови 0.7.1 вручну: завантаж `AiLimits-Setup-0.7.1.exe` зі сторінки
> [Releases](https://github.com/napxlexn/ailimits/releases) і запусти або,
> коли winget уже матиме 0.7.1, виконай `winget upgrade napxlexn.AILimits`.
> Якщо віджет закривається раніше, ніж ти встигнеш, одразу після старту
> натисни на ньому правою кнопкою і спершу зніми **Automatic updates** (або задай
> `auto_update = false` у `%APPDATA%\AiLimits\config.toml`). Починаючи з
> 0.7.1 оновлювач запускає інсталятор напряму, такі шляхи працюють, і
> Automatic updates можна увімкнути знову.

Із термінала:

```powershell
# winget
winget install napxlexn.AILimits

# встановлення одним рядком: тягне останній реліз, звіряє SHA-256
# з опублікованим дайджестом (лише SHA-256, без .sig), запускає тихе
# встановлення для поточного користувача (без прав адміна)
irm https://raw.githubusercontent.com/napxlexn/ailimits/master/install.ps1 | iex

# Scoop, із власного bucket проєкту
scoop bucket add ailimits https://github.com/napxlexn/scoop-ailimits
scoop install ailimits

# Chocolatey
choco install ailimits

# Microsoft Store (підписано й оновлюється магазином), або https://apps.microsoft.com/detail/9P2B0J1VWPWH
winget install --id 9P2B0J1VWPWH --source msstore
```

Або встанови з [Microsoft Store](https://apps.microsoft.com/detail/9P2B0J1VWPWH):
той самий віджет, підписаний і оновлюваний магазином (після релізу може
відставати на кілька днів, поки новий пакет проходить сертифікацію).

Або завантаж `AiLimits-Setup-<версія>.exe` зі сторінки
[Releases](https://github.com/napxlexn/ailimits/releases) і запусти.
Права адміністратора не потрібні (ставиться в `%LOCALAPPDATA%\AiLimits`).
Під час встановлення за бажанням: автозапуск із Windows (відмічено за
замовчуванням), ярлик на робочому столі. winget і Chocolatey запускають цей
самий інсталятор, тож їхня копія самооновлюється, як будь-яка копія з
інсталятора, і менеджер пакетів може показувати старішу версію, ніж запущена.
До кожного релізу також додається portable-zip без інсталятора. Portable-копія
не самооновлюється: її оновлює менеджер пакетів або ти сам. Окремого
portable-режиму для налаштувань немає: кожна копія, зокрема portable, тримає
їх у `%APPDATA%\AiLimits`.

> Інсталятор **не підписаний** цифровим підписом (Authenticode), тож
> Windows SmartScreen може показати «Windows захистила ваш ПК». Натисни
> **Докладніше → Все одно виконати**. Завантаження можна звірити з SHA-256,
> опублікованим у релізі (див. нижче). Починаючи з 0.7.1 кожен реліз також
> має підпис Ed25519 (`.sig`) для інсталятора і zip, і починаючи з 0.7.1
> власний оновлювач застосунку без дійсного підпису нічого не встановлює.
> Оновлювач 0.7.0 на `.sig` не зважає і звіряє лише SHA-256, який GitHub
> публікує для інсталятора: його оновлення до 0.7.1 спирається на цей
> дайджест.

Щоб перевірити завантаження вручну, порівняй його SHA-256 із дайджестом
`sha256:`, показаним біля файлу на сторінці релізу; вони мають збігатися:

```powershell
(Get-FileHash .\AiLimits-Setup-0.7.1.exe -Algorithm SHA256).Hash
```

Щоб перевірити ще й підпис, поклади `.sig` поруч із файлом, обидва під
опублікованими назвами (підпис охоплює назву). Потім у клоні цього
репозиторію, переключеному на тег релізу (`git checkout v0.7.1`), запусти
`verify` підписувача релізів; ключ йому не потрібен (Rust, як у розділі
[Збірка з джерел](#збірка-з-джерел)):

```powershell
cargo run --locked --release --manifest-path tools/release-signer/Cargo.toml -- verify $HOME\Downloads\AiLimits-Setup-0.7.1.exe
```

Він друкує `verified` або `NOT verified` із причиною.

Інсталятор не містить ключів і токенів. При першому
запуску віджет не читає жодного з описаних нижче джерел авторизації, поки ти
не дозволиш.

### Видалення

Видалення у Windows (Settings, Apps), через
`winget uninstall napxlexn.AILimits` або через `choco uninstall ailimits`
запускає деінсталятор, встановлений разом із застосунком. Він закриває
AI Limits і без звернення до мережі видаляє: теку встановлення,
`%APPDATA%\AiLimits` (налаштування, кеш, логи), кожен запис у Credential
Manager, який зробив застосунок (ключі, токени, сеанс Cursor), значення
автозапуску і реєстрацію сповіщень.

Видалення копії зі Scoop чи portable-копії нічого з цього не прибирає:
`scoop uninstall ailimits` або видалення теки забирає лише файли самого
застосунку. Перш ніж її прибрати, закрий AI Limits і виконай у її теці
(якщо видаляти нічого, команда просто нічого не робить):

```
ailimits-auth remove claude
ailimits-auth remove copilot
ailimits-auth remove-usage-token claude
ailimits-auth remove-usage-token codex
ailimits-auth logout cursor
```

Потім видали `%APPDATA%\AiLimits` і ключ реєстру
`HKCU\Software\Classes\AppUserModelId\napxlexn.AILimits` (назва й іконка, з
якими показуються тости застосунку). Копія з Microsoft Store: як спершу
прибрати її ключі, описано в [docs/uk/CONFIG.md](docs/uk/CONFIG.md#секрети);
її видалення забирає й її власну теку налаштувань (теку копії зі Store
описано на початку того файлу).

## Швидкий старт

1. **Запусти.** При першому старті відкривається вікно привітання (те саме,
   що *Settings…* у меню). Його запитання перелічує знайдені на
   цьому ПК інструменти (Claude Code, Codex CLI, Copilot CLI чи GitHub CLI,
   Antigravity, Grok CLI, Cursor), кожен із
   галочкою, і називає кожен файл, який буде прочитано, і куди йде кожен
   токен. Інструменти, знайдені за власною текою, відмічені одразу; сам
   GitHub CLI (для Copilot) чи сама `.gemini` (для Antigravity) показані без
   галочки. *Allow* запускає відмічені; *Cancel* нічого не читає, і ти
   відмічаєш потрібні сам, а кожен інструмент один раз питає. Вікно не
   забирає фокус клавіатури (Enter нічого не дозволяє випадково) і чекає,
   поки на передньому плані повноекранна програма. Як і *Settings*,
   воно лишається відкритим, поки його не закриє Esc, хрестик чи Alt+F4, і
   переміщується за заголовок. Cursor один раз потребує
   власного входу застосунку: у тому самому вікні розгорни рядок *Sign-in*
   під Cursor і натисни *Sign in to Cursor…*. Після оновлення з 0.7.0
   нічого робити не треба: твої провайдери працюють далі, а одне вікно
   перелічує, що читається.
2. **Постав на місце.** Тягни лівою кнопкою; **Shift** під час перетягування
   притягує віджет впритул до найближчого краю робочої області монітора
   (екран без панелі завдань), щойно до цього краю лишається менше ніж 64 px;
   `Lock position` (ПКМ) фіксує.
3. **Обери вигляд.** ПКМ → рівень деталізації (Compact / Medium / Expanded),
   розкладка (Rows / Columns), палітра (монохром або 8 кольорів),
   прозорість, яскравість і насиченість. Усе це показано на анімаціях вище.
   Досить навести курсор на такий пункт, а також на Width, Column layout чи
   Usage forecast, і віджет, панель та іконка трею одразу його показують; так
   само, коли переходиш до нього клавіатурою. Закриєш меню без кліку, і все
   повернеться.
   *Settings…* вибирає рядки, які показують віджет і підказка панелі
   (зокрема додаткові, як-от тиждень Opus у Claude), необов'язковий підпис
   моделі, якою ти користуєшся (модель, версія, reasoning effort), і звідки
   береться вхід кожного провайдера. *Model source* вибирає, звідки підпис
   бере модель: *Tool settings* або *Last session* — модель найновішого сеансу
   Claude Code чи Codex CLI, прочитана з кінця його файлу (щонайбільше
   останній 1 МБ); для інших інструментів показується модель, задана в
   налаштуваннях.
   Колонка Taskbar вибирає два провайдери, яких показують панель та іконка
   трею; щонайменше один лишається відміченим. Percentage і Time to reset
   відмічаються окремо для підказки панелі (колонка Tooltip) і для самої
   панелі (колонка Taskbar): відсоток, час до скидання ліміту чи обидва;
   останній увімкнений зняти не можна. Progress bar (за замовчуванням
   увімкнено) може прибрати смужку панелі, щоб вона займала менше місця на
   таскбарі.
4. **Наведи курсор на рядок провайдера**, щоб замість часу скидання побачити
   його тижневий ліміт (у Compact — у нижньому рядку). Сірий або `≈`-рядок
   натомість пояснює себе під курсором: причина і що зробити, наприклад
   `token expired — run Claude Code`. Причину видно повністю в рядках Medium
   і Expanded та в нижньому рядку Compact (на ширині 100% і 75%), а під
   колонкою Expanded — скорочену, щоб умістилась; колонки Compact і Medium та
   Compact на 50% її не показують.
5. **Віджет заважає?** ПКМ → **Taskbar** → *Taskbar panel* або
   *Tray icon*. Коли віджет прихований чи перекритий іншими вікнами,
   використання лишається на панелі завдань; поки екран займає повноекранна
   програма, показник ховається разом із панеллю завдань і повертається,
   щойно ти з неї вийдеш. Див.
   [Індикатор на панелі завдань](#індикатор-на-панелі-завдань).
6. **Лівий клік по трей-іконці чи панелі** виносить віджет на передній план
   або ховає. Правий клік по трей-іконці чи будь-де на панелі відкриває те
   саме меню.
7. **Замість рядків напис?** *Setup required* чи *No data yet*:
   клацни по віджету, і відкриється *Settings*.
   *Right-click → set up providers*: провайдери відмічені, але жоден із них
   не має входу; перевір *Sign-in* кожного провайдера в *Settings*.

## Як працює авторизація

Віджет ніколи не просить логінитись, окрім одного разу для Cursor. Він
моніторить ліміти **підписок**, повторно використовуючи токени, які
офіційні CLI тримають на твоїй машині, строго read-only і лише після того, як
ти дозволиш кожен:

| Провайдер | Автоматичне джерело (за замовчуванням) | Щоб увімкнути |
|---|---|---|
| Claude | `%USERPROFILE%\.claude\.credentials.json` (OAuth-токен Claude Code) | запустити [Claude Code](https://claude.com/claude-code) хоч раз |
| Codex | `%USERPROFILE%\.codex\auth.json` (токен Codex CLI; у `CODEX_HOME`, коли її задано) | один раз `codex login` |
| Copilot | `gh auth token --hostname github.com` (GitHub CLI) | один раз `gh auth login` |
| Antigravity | Windows Credential Manager target `gemini:antigravity` | запустити `agy`, тобто Antigravity CLI; його токен живе близько години, і оновлює його лише `agy` (відкриття редактора — ні) |
| Grok | `%USERPROFILE%\.grok\auth.json` (логін Grok CLI; у `GROK_HOME`, коли її задано) | один раз запустити `grok` і залогінитись (підписка SuperGrok) |
| Cursor | власний сеанс віджета у Windows Credential Manager (`cursor_session`); нічого з редактора Cursor для цього не читається | Один раз увійти в Cursor у *Settings* (*Sign-in* під Cursor, *Sign in to Cursor…*) або через `ailimits-auth login cursor`: у браузері відкривається власна сторінка входу Cursor; сеанс на ~60 днів |

Під рядками кожного провайдера на вкладці *Providers* у *Settings* є рядок
*Sign-in*, який каже, звідки береться вхід і як він спрацював ("Claude Code ·
connected"). Розгорни його, щоб вибрати джерело: обліковий запис
інструмента з таблиці вище (*Claude Code account* тощо) або,
для Claude, Codex і Copilot, твій власний ключ чи токен (див. Ручну
авторизацію нижче). Використовується лише вибране джерело; коли воно не
спрацьовує, жодне інше його не підміняє.

Про кожен інструмент питає один раз. Якщо зняти всі рядки провайдера
(Widget, Tooltip і Taskbar), він стає на паузу: нічого з нього не
читається й не надсилається, а галочка знову запускає його без запитання.
Щоб відкликати дозвіл, розгорни його *Sign-in* і натисни *Forget
permission* (показується, поки джерелом є власний вхід інструмента): його
вхід більше не читається, рядки знімаються, а наступна галочка знову
питає. Сеанс Cursor завершує *Sign out*, вставлений ключ чи токен прибирає
*Remove*. Для читань підпису моделі є окреме посилання *Forget
permission* на вкладці *Display*, під Model, Version і Reasoning effort. Дозволи
зберігаються окремо для кожного користувача Windows, у його `config.toml`.

Codex CLI пише `auth.json`, лише коли тримає свій вхід у файлі: з
`cli_auth_credentials_store = "keyring"` чи `"auto"` у його `config.toml`
`auth.json` немає, і його вхід прочитати неможливо. Постав `"file"` або
натомість встав usage-токен.

Це **OAuth access tokens**, короткоживучі, крім токена Cursor; CLI-власник
оновлює кожен щоразу, коли ти ним користуєшся. Віджет ніколи не оновлює
токен чужого застосунку, бо OAuth-refresh ротує токен і розлогінив би CLI.
Сеанс Cursor (близько 60 днів) належить віджету: ти входиш у Cursor у
браузері, на власній сторінці Cursor, а віджет сам зберігає й оновлює цей
сеанс. Cursor не має входу для інших застосунків, тож віджет входить від
імені клієнта редактора Cursor; вхід самого редактора він ніколи не читає.
`CODEX_HOME`, `GROK_HOME` і `COPILOT_HOME` враховуються лише як абсолютні
шляхи.

### Скільки дані лишаються точними без жодних дій

| Провайдер | Живі дані тривають | Після цього |
|---|---|---|
| **Claude** | ~8 годин після останнього сеансу в Claude Code (реальний час життя токена) | останнє значення сірим, із давністю |
| **Codex** | поки користуєшся Codex CLI (скільки живе його токен, ще не виміряно) | останнє значення сірим, із давністю |
| **Copilot** | Нескінченно. gh тримає токен свіжим, поки ти залогінений. | |
| **Antigravity** | близько години після останнього запуску `agy` (його токен оновлює лише `agy`) | останнє значення сірим, із давністю |
| **Grok** | до ~6 годин після останнього сеансу в Grok CLI (реальний час життя токена) | останнє значення сірим, із давністю |
| **Cursor** | близько 60 днів після входу (час життя сеансу) | останнє значення сірим і `sign in to Cursor again` |

Google припинив обслуговувати Gemini CLI для individual, Google AI Pro і
Google AI Ultra користувачів 18 червня 2026 року. Шлях міграції для них це
Antigravity CLI; віджет читає лише token Antigravity із Windows Credential
Manager, а legacy-файл Gemini CLI більше не читає. Google заблокував деякі
акаунти за використання входу Antigravity поза Antigravity. Віджет лише
читає твою квоту, раз за оновлення, але ризик твій: запитання, що просить
дозволу читати вхід Antigravity, про це каже.

**У Claude є серверна стеля свіжості:** Anthropic обмежує usage-endpoint
(HTTP 429, `Retry-After: 0`, перевірено 2026-07-09), а per-token бакет
ділиться з опитуванням самого Claude Code, тож поки Claude Code активний,
оновлення Claude інколи займає 2–3 хвилини навіть на 1-хвилинному
інтервалі. Наступний цикл питає знову через інтервал оновлення; очікування
зростає (2, 4, далі щонайбільше 5 хвилин при 1-хвилинному інтервалі), лише
коли за цикл жоден провайдер не приніс даних, а обмеження частоти теж
вважається відсутністю даних. Тим часом рядок Claude під курсором пише
`rate-limited, retrying`. Решти провайдерів це не стосується.

Протухлий токен Claude/Codex/Antigravity/Grok/Cursor ніколи не означає неправильних цифр:
останнє значення лишається сірим із давністю, гарантовано скинуте вікно
показує `≈0%`, а відлік до скидання тікає локально. Якщо користуєшся CLI щодня, живі
дані будуть майже весь час.

### Ручна авторизація (для незалежності або без CLI)

Для сетапів без CLI або облікових даних, що не залежать від активності CLI.
Що реально вартий кожен варіант:

| Провайдер | Ручний варіант | Звідки взяти | Показує те саме, що підписка? |
|---|---|---|---|
| **Copilot** | Fine-grained Personal Access Token; дозволи йому не потрібні зовсім (лиши порожніми) | github.com/settings/personal-access-tokens, *Generate new token* | Перевірено живим запитом 2026-11-21: токен без жодного дозволу читає ті самі квоти, що й вхід GitHub CLI. Працює без gh, до терміну, який ти задаси. |
| **Claude** | API ключ | console.anthropic.com, Settings, API Keys, *Create Key* (`sk-ant-…`) | Ні. Це ліміти твого API-акаунта, а не підписки Pro чи Max. |
| **Codex** | Немає | Окремого стабільного токена не існує. Вставлений *Usage token* — такий самий OAuth-токен, як у Codex CLI. | |
| **Antigravity** | Немає | Квота прив'язана до OAuth-токена, який оновлює Antigravity CLI, і окремого ключа з тими самими цифрами не існує. | |
| **Grok** | Немає | Тижневий ліміт SuperGrok читається лише з власним логіном Grok CLI. | |
| **Cursor** | Власний вхід, близько 60 днів | *Settings*, *Sign-in* під Cursor, *Sign in to Cursor…* або `ailimits-auth login cursor` | Так. Це використання самої підписки. |

**Два способи додати облікові дані:**

1. **У *Settings*.** Скопіюй ключ чи токен. Розгорни рядок *Sign-in*
   провайдера, вибери джерело (*Claude*: *Usage token* або *API key*;
   *Codex*: *Usage token*; *Copilot*: *Fine-grained token*) і натисни
   *Paste token from clipboard*
   (*Paste key from clipboard* для API-ключа Claude). Приймається лише
   такий секрет (`sk-ant-...`; `ghp_...`, `github_pat_...`, `gho_...`,
   `ghu_...` чи класичний 40-символьний hex-токен; токен ChatGPT
   `eyJ...`): усе інше в буфері відхиляється без надсилання й ніде не
   показується й не логується. Usage-токен спершу перевіряється одним
   запитом: відхилений не зберігається. Ключ зберігається як є, а рядок
   покаже, чи він працює. Вікно каже, чим це закінчилося (тост, якщо вікно
   тим часом закрили), а секрет одразу йде в Credential Manager.
   Використовується лише вибране джерело: поки вибрано твій токен чи ключ,
   вхід інструмента не читається, а поки вибрано обліковий запис
   інструмента, збережений токен не надсилається.
2. **З терміналу.** `ailimits-auth.exe` лежить поруч із віджетом
   (`%LOCALAPPDATA%\AiLimits`):
   ```
   ailimits-auth status                       # показати всі виявлені джерела
   ailimits-auth set copilot                  # зберегти PAT (прихований ввід)
   ailimits-auth set claude                   # зберегти API ключ Claude
   ailimits-auth set-usage-token claude|codex # зберегти ручний usage-токен
   ailimits-auth remove copilot|claude
   ailimits-auth remove-usage-token claude|codex
   ailimits-auth login cursor                 # увійти в Cursor у браузері
   ailimits-auth logout cursor                # забути цей сеанс
   ```
   `set-usage-token` перевіряє токен одним запитом до usage-endpoint'а
   провайдера: відхилений (401/403) не зберігається; обмеження частоти (429)
   вважається прийняттям; без відповіді, яка б сказала так чи ні, питає
   знову через 2 і 4 секунди, а далі зберігає з приміткою. `status` нічого не
   змінює і читає вхід іншого інструмента лише там, де може віджет. Запущений
   віджет сам підхоплює те, що змінюють інші команди, без перезапуску:
   змінене налаштування — за кілька секунд, новий чи видалений ключ або
   токен — при наступному оновленні. `set` і `set-usage-token` роблять
   збережене джерелом провайдера.

**Повернутися до входу інструмента:** у *Sign-in* провайдера вибери
обліковий запис інструмента (*Claude Code account*, *Codex CLI account* чи
*GitHub CLI account*). Твій ключ чи токен лишається збереженим, але не
використовується; *Remove*, коли вибрано його джерело, видаляє його. З
терміналу `ailimits-auth remove claude|copilot` видаляє ключ і перемикає
назад; `remove-usage-token` видаляє токен, але лишає джерело на ньому, тож
рядок ховається, доки ти не вибереш обліковий запис інструмента у вікні.

## Контекстне меню

ПКМ на віджеті:

- `Settings…`: рядки, підписи моделі, псевдоніми моделей, вхід кожного
  провайдера.
- **Detail**: Compact / Medium / Expanded.
- **Layout**: Rows / Columns, далі Width (100 / 75 / 50%, сірий, якщо не
  Rows) і Column layout (Side by side / Stacked, сірий, якщо не Columns).
- **Appearance**: Palette (8 кольорів), Monochrome, Background opacity,
  Brightness, Saturation.
- **Taskbar**: Tray icon / Taskbar panel / None, і Panel display, коли
  таскбарів більше одного.
- `Always on top` і `Lock position` (два незалежні перемикачі), Usage
  forecast (burn-rate «~час до ліміту», вимкнений за замовчуванням).
- Refresh interval (1 / 5 / 15 / 30 min) і `Automatic updates` (тихе фонове
  самооновлення копії з інсталятора, увімкнено за замовчуванням; у копіях зі
  Store, Scoop, портативних і зібраних власноруч такого пункту немає).
- *AI Limits 0.7.1* зі значком GitHub (відкриває сторінку проєкту) і Quit.

Usage forecast показує свій ~час у рядках Medium і Expanded та в колонках
Expanded, лише там, де час скидання невідомий, і ніколи для даних, які
перестали оновлюватись.

### Індикатор на панелі завдань

Коли overlay прихований або перекритий іншими вікнами, компактний показник
використання лишається на панелі завдань; поки екран займає повноекранна
програма, він ховається разом із панеллю завдань і повертається, щойно ти з
неї вийдеш. ПКМ → **Taskbar**:

- **Tray icon** (за замовчуванням). Одна 16px іконка в системному треї: два
  концентричні кільця для тих самих двох провайдерів, яких показує панель
  (перших двох у віджеті або двох, відмічених у колонці Taskbar вікна
  *Settings*), завантаженіший зовні, обидва ростуть за
  годинниковою стрілкою від 12-ї. Монохромна, у кольорі теми системної
  панелі завдань.
- **Taskbar panel.** Прозорий overlay поруч із годинником. Немає ні вікна, ні
  прямокутника, лише цифри розміру годинника й смужки поверх таскбару.
  Монохромний, слідує світлій і темній темі системи, показує перші два
  провайдери в порядку віджета або два, відмічені в колонці Taskbar вікна
  *Settings*, з відсотком (і його смужкою, якщо там не знято Progress
  bar), часом до скидання ліміту або обома (значення, яке перестало
  оновлюватись, чи оцінка `≈` малюється блідіше, як віджет робить його сірим)
  і стежить за таскбаром, коли той рухається (авто-приховування, зміна
  роздільності, ширина трея). При наведенні дає tooltip з рядками,
  позначеними в колонці Tooltip (за замовчуванням усі провайдери), кожен із
  відсотком і часом до скидання. Якщо Пуск, Пошук або auto-hide бар
  перекриває панель, індикатор передає роботу кільцям у треї й сам
  повертається. Якщо екран займає повноекранна програма, панель ховається
  разом із таскбаром і повертається, щойно ти alt-tab-нешся назад. Працює з
  таскбаром на будь-якому краю екрана: на боковому барі два провайдери стають
  у стовпчик, відсоток над смужкою, над треєм. Бар, де між останньою кнопкою
  застосунку і треєм немає вільного місця, панелі не отримує: доки там не
  з'явиться місце, працюють кільця в треї, тож панель ніколи не лягає на
  кнопки.
- **None.** Без індикатора.

Якщо Windows показує таскбар на більш ніж одному дисплеї, **Taskbar →
Panel display** вибирає, до якого таскбару кріпиться панель. Це підменю з'являється
лише коли існує другий таскбар; якщо обраний дисплей потім зникає (від'єднано),
панель повертається на основний таскбар. Меню будується під час запуску
застосунку, тож дисплей, під'єднаний пізніше, з'явиться в ньому після
перезапуску. *Display 2*, *Display 3* і далі — це інші таскбари, пронумеровані
зліва направо, а не за номерами дисплеїв у Windows.

Лівий клік по іконці трею чи по панелі виносить віджет на передній план (або
ховає, якщо він уже спереду, зверху); правий клік **будь-де на панелі**
відкриває це саме меню.

## Конфіг і діагностика

`%APPDATA%\AiLimits\config.toml` створюється автоматично, і кожна зміна з меню
зберігається туди. Правки, збережені в ньому, діють, поки програма працює,
приблизно за дві секунди й без перезапуску; *Edit config.toml…* в кінці
вкладки *Display* у *Settings* відкриває його в Блокноті. Рядок, що не читається,
пропускається й називається, а діє його значення за замовчуванням. Файл
пояснює себе сам: коротка примітка перед кожним налаштуванням каже, що воно
робить, які значення приймає і яке значення за замовчуванням. Довідник
формату: [docs/uk/CONFIG.md](docs/uk/CONFIG.md).
Тонке налаштування поза меню (розміри, кольори, пороги): [docs/uk/TUNING.md](docs/uk/TUNING.md).

Задай `AILIMITS_LOG=ailimits=debug` або `RUST_LOG=ailimits=debug`, і
діагностичний лог писатиметься у `%APPDATA%\AiLimits\ailimits.log` (stderr у
GUI-застосунку невидимий). Файл ротується на 5 МБ: попередній зберігається як
`ailimits.log.1`.

Аварія лишає один рядок у `%APPDATA%\AiLimits\crash.log` (час, версія,
потік, місце в коді; ніколи текст повідомлення аварії); невдалий старт каже
про це повідомленням і в цьому файлі. Повторний запуск AI Limits, коли він
уже працює, показує й піднімає віджет.

Тост про поріг приходить один раз на вікно ліміту, коли використання
досягає `alert_threshold` провайдера (за замовчуванням 80%, для Copilot
85%); знову — лише після скидання вікна або коли використання впало більш
ніж на 5 пунктів нижче порогу й знову піднялося. `[notifications]` у
конфігу вимикає тости (`enabled = false`) і задає найкоротший проміжок між
двома тостами одного провайдера (`cooldown_minutes`).

Запити йдуть через проксі, заданий у Windows (Settings, Network, Proxy,
«Use a proxy server»); `HTTPS_PROXY`, `HTTP_PROXY` і `ALL_PROXY` мають пріоритет, скрипт
проксі (PAC) не підтримується. `ailimits-auth` іде лише за змінними, а не
за налаштуванням Windows. Мережа, що перевіряє TLS власним кореневим
сертифікатом, довіри не має: рядки пишуть "untrusted certificate, retrying".

## Збірка з джерел

Потрібен Rust 1.90 або новіший із тулчейном MSVC: Visual Studio Build Tools
із набором для C++ і Windows SDK, чий `rc.exe` вбудовує іконку, маніфест і
версію (див. `build.rs`). Інсталятор збирається Inno Setup 6.7.4 з exe
профілю `release-min`. Копія, запущена з `target\`, не самооновлюється й не
має пункту *Automatic updates*.

```
# Rust 1.90+ (MSVC), Windows 11
cargo build --profile release-min --locked   # ~4 МБ exe у target/release-min/
cargo test --locked
ISCC.exe installer\ailimits.iss              # інсталятор, у target/installer/
```

Документація для розробників: [docs/en/](docs/en/) (англійська),
[docs/uk/](docs/uk/) (українська).
